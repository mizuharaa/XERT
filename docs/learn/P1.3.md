## What changed

Added optional **temporal ensembling**: the ACT-style policy predicts a new
action chunk on every fresh observation, then averages predictions from still
active chunks for the current tick. An action chunk is a sequence of future
joint targets. Exponential weights favor newer predictions; they never mix
actions for different future ticks. Reset clears the prediction history between
episodes. Existing checkpoints retain their original non-overlapping execution.
This newer-favored choice differs from [upstream ACT's older-favored weighting](https://github.com/tonyzhaozh/act/blob/main/imitate_episodes.py).

The checkpoint records execution choice and decay. A regression test uses known
chunks to check alignment, weights, fresh queries, and reset. Evaluation accepts
an explicit slice label so ledger rows correctly identify P1.3.

## Experimental design

[`configs/act_experiment.json`](../../configs/act_experiment.json) was committed
before training and held-out evaluation: chunk lengths 10/20/50 each received
3 sweep epochs, and the lowest validation action error selected 50 (ledger rows
`f720d85f-1301-4f48-8206-d57fd2bbc1ca`, `7e2bf5fc-283a-4a78-8380-33e203bb2d92`,
`bc29a2b6-063b-4789-af7d-9b35c008d7b7`). Training seeds 0/1/2
then each received 20 epochs, with 30 held-out evaluation seeds per model. Every model was evaluated on the same held-out initial-state seeds;
the reported Wilson interval is computed separately for each training seed.
Reusing evaluation seeds across models does not create additional independent
trials, so results are not pooled.
Selection scores all future chunk positions, not ensembled rollout performance;
changing chunk length changes that forecasting task. Training seeds also change
the episode-level training/validation split, not just network initialization.

Training uses the P1.2 noisy **scripted** demonstrations and verified corrective
labels. The experiment copies immutable episode artifacts into its own store,
retains all model checkpoints and evaluation trajectories, and refuses an
existing output directory. No scripted expert fallback or time-only diagnostic
mask is used by the evaluated policy. The continuous gripper head is retained:
P1.1 did not identify a missing binary action decoder.

Reproduce with `python -m scripts.experiment_act --output <new-directory>`.
This bounded CPU experiment does not establish convergence or optimal settings.
It combines recovery data, training budget, chunk selection, and ensembling;
without an ablation it cannot attribute improvement to ensembling alone, and
its different evaluation seeds prevent a direct comparison to historical results.
Generated evidence can make evaluation ledger rows report `git_dirty=true`;
that flag is retained while source files stay frozen at the recorded commit.
Its simulator-state observations do not establish camera perception, SO-101
hardware performance, or a human-demonstration quality-gate result.

**Interview question:** What does temporal ensembling change?
**Answer:** It combines several predictions for the same current action while
still using a fresh observation every tick, instead of blindly finishing an
old action chunk.
