# P1.2 — Demonstrations with corrective labels

Collected **100 scripted MuJoCo episodes**, containing **44,480 transitions**,
from seeds 100–199. The perturbed expert completed **100/100** episodes. These
are collection outcomes, not learned-policy or hardware results. The dataset,
resolved configuration and measurements are linked by the `P1.2` ledger rows
in [`results/ledger.jsonl`](../../results/ledger.jsonl); the collection manifest
is [`collection.json`](../../results/p1.2/recovery_v1/collection.json).

The configuration was committed before collection. Every episode is retained;
there is no success filtering. Seeds 0–15 and 10000–10029 remain excluded from
the demonstration dataset. All environments use the existing observation,
action, timing and physical-model contracts.

## What changed and why

`collect` accepts `action_noise_std`, exposed as `xle collect
--action-noise-std`. At each actual simulator state, it first asks the scripted
expert for a corrective target, then adds Gaussian noise to the arm targets
that are executed. Gripper targets are unchanged. This is **DART-style noise
injection**: deliberately visiting nearby imperfect states while recording the
expert's attempted correction. The fixed noise scale is a declared experiment
setting, not an optimized DART covariance or a claim of robust recovery.

`episode.npz` continues to contain the actions actually executed. Therefore
ordinary replay still reconstructs the recorded physics. A separately hashed
`corrective.npz` contains the expert labels and the matching states, rewards
and termination flags. The existing bounded archive decoder is reused. Before
training, the loader checks its provenance, checksum, dimensions, finite bounded
actions and exact transition alignment. Missing labels fail explicitly.

Training uses the corrective payload, and checkpoint metadata records its hash
and source. The learner's episode fingerprints cover the labels it actually
sees. No observation/action schema or real-motor code changed.

The runnable regression check is `python -m pytest tests/test_recovery.py -q`.
It compares every label with the expert at the perturbed state, replays the
executed controls, checks training fingerprints, and rejects missing, corrupt
or misaligned labels. Full pytest and CTest checks pass before and after this
slice.

Reproduce into a fresh directory with `python -m scripts.collect_recovery
--output <new-directory>`. Existing artifact directories are never overwritten.

**Interview question:** Why are executed actions and training labels different?
**Answer:** The disturbance creates a recovery state, while the clean expert
target teaches what the controller should do there instead of teaching it to
repeat the disturbance.

This dataset does not prove that a learned policy recovers successfully. The
expert also follows a fixed task schedule, so it is not a general recovery
planner; P1.3 measures the learner separately on held-out initial states.
