# P3.4: one simulation backend, several robot bodies

`Backend` exposes only a specification, measured joint state, position-target
commands, and close. `MuJoCoBackend` resolves joint and actuator names from that
specification. An actuator is the simulation component that applies force to move
a joint. This implementation deliberately supports direct, unit-gear position
actuators; it rejects torque controllers and ambiguous mappings.

The backend starts at the spec's rest pose, advances a whole number of physics
steps per control tick, and returns copied joint positions, velocities and
simulation time. It refreshes derived tool poses after integration so recorded
poses correspond to the returned joint state. It rejects malformed targets, target positions outside bounds,
repeated timestamps, and use after closing. The separate safety controller limits
command changes before the backend receives them. Simulation engine faults latch
the backend closed. Spec speed and acceleration limits are simulation configuration
defaults, not measured hardware limits.

Alongside actual SO101 and the older XLeRobot arm, pinned Menagerie assets now
provide G1 and LEAP. Each vendor folder retains upstream license, immutable
commit and file hashes. `prepare_embodiments.py` removes G1's floating base joint,
legs and their actuators, leaving a fixed pelvis with waist and arms. It adds
wrist-frame tool sites. LEAP keeps its fixed palm and gains sites at the compiled
fingertip geometry centers. Upstream source XML remains unchanged beside derivatives.

`scripts/drive_embodiments.py` reads one explicitly **scripted** motion file.
Its neutral-relative XYZ offsets map through each spec to tool targets, then
the same IK, safety controller, and backend drive every body. Run it with
`--specs xert/spec/so101.yaml xert/spec/g1_upper.yaml xert/spec/leap_hand.yaml`
and a new `--output` path. The resulting state/command records and ledger rows
are simulation integration evidence, not human demonstrations or task success.

Acceptance tests compare the shared clip against a zero-offset control for every
body, so gravity-induced motion alone cannot pass. A copied LEAP spec with
an unseen robot name also runs through the same path while controller file hashes
remain unchanged. No robot-name dispatch is needed. This does not establish
collision-free trajectories or comparable tracking quality across embodiments.

**Interviewer question:** What actually changes when adding a robot?

**One-sentence answer:** Its licensed model and validated specification change;
the solver, command safety rules and simulation backend stay the same.
