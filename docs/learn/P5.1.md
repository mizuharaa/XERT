# P5.1: gate metrics (software only)
The metric code is implemented; **acceptance remains unmeasured**. Acceptance
means distributions over collected human demonstrations (P4.2), and none exist
yet. Tests use hand-built arrays and scripted recordings in temporary folders.
Scripted data never produces ledger rows: `--ledger` refuses any recording whose
manifest source is not `webcam` or `recorded_human`.
`xert/data/quality.py` reads a LeRobot v3 runtime recording through
`load_runtime_dataset`, which keeps float64 timestamps. It computes one row per
episode. An episode is one continuous recorded attempt at the task.
**Action jitter** is the root-mean-square (RMS) of the second difference of the
commanded joint targets (`action`): `a[t+1] - 2a[t] + a[t-1]`, over all joints,
in radians per control step squared. The second difference is a discrete
acceleration, so a smooth motion scores low and a shaky one scores high.
**Command gap** is the largest interval between consecutive host command times
(`t_command`); the nominal value is one control period. **Capture gap** is the
largest interval between capture times of distinct source frames.
The control loop repeats the last frame when no new one arrives, so a repeated
`frame_sequence` is a held frame, not a new capture. **Dropped-frame fraction**
uses the webcam's capture counter: the share of sequence numbers between the
first and last applied frame that were never applied. Drops before the first or
after the last applied frame cannot be seen. **Tracking confidence** is null
today and stays null. Handedness scores measure left/right classification, so
they are reported separately as `mean_handedness_score`. **Clamp count** is the
number of steps where the safety layer changed the command (`xert.clamped`).
**Success** is true if any frame's `next.success` is true. It is null when that
feature is missing; it is never guessed. **Duration** is frames divided by rate.
`verdict(metrics, thresholds)` returns pass/fail plus reasons. A metric that is
unavailable fails, and an unknown threshold name raises an error, so a typo
cannot quietly disable a check. No thresholds are committed: P5.2 chooses them.
Run `python -m xert quality --dataset <recording> --output <fresh dir>` in the
LeRobot environment. It writes `metrics.json` (episodes plus histogram bin
counts) and `episodes.csv`. No plotting library is installed, so there are no
image plots. Add `--ledger` for human data to append median rows.
