# P3.6: retarget quality on a recorded clip (pending acceptance)
The software is implemented; **acceptance is pending a real webcam clip**.
Scripted test clips check the code paths only. They never append ledger rows.
Retarget error per robot: **TBD (not measured)**. No real motors are used.

Retargeting turns human motion into robot commands. The end effector (EE) is
the robot part that does the work, such as a gripper or fingertip. A target in
task space is a requested 3D position. Joint space is the list of joint angles.
Forward kinematics (FK) computes site positions from joint angles. Inverse
kinematics (IK) finds joint angles for a requested site position.

`python -m xert record-motion` opens the selected webcam after a countdown.
It saves landmarks, timestamps, handedness scores and image size, never pixels.
The file also records the camera index, the pinned model checksum and the git
commit. It has the same model check, fresh-path rule and Escape/Ctrl-C stop as
`calibrate`. `MotionFileSource` replays a clip at its recorded timing on the
loop clock. It moves the timestamps onto that clock and delivers only the
latest frame that is due, as the webcam slot does. Webcam files replay as
`recorded_human`. Scripted files replay as `scripted`.

`scripts/measure_retarget.py` runs the clip through each robot's calibrated
mapper, safety layer and MuJoCo backend. The run uses simulated time, so
results repeat exactly and host speed cannot cause overruns. P3.5 measures
real latency separately. For each unique applied frame, the script compares
each target with the achieved site position after that frame's first step.
- **SO-101, G1:** the target is the mapper's requested IK site position.
  Orientation and gripper commands are requested but not scored.
- **LEAP:** finger-bend changes map straight to joints, so no IK target exists.
  The target is the FK fingertip position of the requested joint vector. This
  is not human fingertip error.

**Calibration pairing:** the clip calibrates itself. For each robot, neutral is
the first frame that shows every hand the robot maps. That frame is excluded
from scoring. Neutral and motion then share one camera session and framing.
Hold still for the first two seconds of the recording.

Errors include IK residual (unreachable targets), safety limiting, one-step
servo lag and servo sag under gravity. Targets are neutral-relative control
coordinates, with palm size as a depth proxy, not metric human motion. Rows
(`retarget_ee_err_mm_p50`/`_p95`, `n` = frame-site samples) are built and
validated for every clip. They are appended only when the clip's source is
`webcam`, and only after every robot finishes.
Commands: `python -m xert record-motion --output results/p3.6/clip.json
--duration 30`, then `python scripts/measure_retarget.py --clip
results/p3.6/clip.json --output results/p3.6/run`.
**Interview question:** Why score LEAP at FK fingertips instead of against the
human's fingertips?
**Answer:** The mapping only uses bend changes from neutral, so the code has no
metric human fingertip target; FK of the requested joints is the target it
actually produces.
