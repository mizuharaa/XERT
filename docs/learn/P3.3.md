# P3.3: command limits and stale-input watchdog

The safety controller limits requested joint positions, velocity (change in
position per second), and acceleration (change in velocity per second), using
the embodiment specification. It reserves the distance required to brake at
both position limits and the requested target on later control ticks. Without
that reservation, clipping a position at its limit
can suddenly violate an acceleration limit.

The controller accepts a fixed-rate command clock matching the spec. Each input
carries its capture timestamp. Invalid dimensions, nonfinite numbers, future
capture times, reversed capture times, or a broken control clock fail explicitly.
These are limits on **commanded positions in simulation**, not measured motor
motion, collision avoidance, or certified hardware safety.

A watchdog detects missing or stale input. It requests a hold at the last
commanded pose, then a smooth transition toward the configured rest pose.
The same motion clamps also apply to that transition, so braking and speed
limits may delay arrival at rest. Only fresh valid input resets the timeout and
resumes live control; delayed frames cannot rewind a return already in progress.

The UI key hook `handle_key("Escape")`, or `estop=True`, latches an immediate hold;
later input cannot restart it. Constructing a new controller is an explicit
reset. The latch survives an invalid target or clock in the same call.
Emergency hold intentionally overrides acceleration limits, because an
emergency stop must not continue the normal requested trajectory.

Each changed command has a clamp event containing time, joint indices, requested
positions and applied positions. Watchdog transitions are recorded too; callers
can persist the per-step events and clamp flag alongside data. Tests drive both
position boundaries, reverse direction, drop input, reach rest, and check the
latched emergency stop. Existing Python and CTest gates run before and after.

**Interviewer question:** Why does a position clamp need braking distance?

**One-sentence answer:** A command moving toward a limit must start slowing before
it arrives, or stopping at the boundary can exceed its acceleration limit.
