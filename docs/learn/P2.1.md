# P2.1 — Lossless LeRobot v3 export

**Measured simulation-data export:** every P1.2 episode and transition was
reconstructed through the installed LeRobot loader. Ledger row
`d56c4f9e-d897-4f97-9574-a60775da2b77` holds the maximum absolute float32 error
and frame count, and links the [verification](../../results/p2.1/legacy_v3/roundtrip.json) and
[source manifest](../../results/p2.1/legacy_v3/xert_export.json), measured from
clean implementation commit `d4cd96f`. This is format-conversion evidence,
not a learned-policy or hardware result.

## What changed

Added an optional exporter that uses the official `LeRobotDataset` writer and
loader. LeRobot v3 stores time-series arrays in Parquet, a tabular binary format,
with metadata describing features and episode boundaries. The existing NPZ
format and shared simulation dependencies remain unchanged.

Each output row represents one original transition: observation, action, reward,
termination flag, and next observation. Keeping the successor preserves the
terminal observation without inventing an extra action. The training action is
the checksum-verified expert correction when available; a separate feature
retains the command that actually ran. All privileged simulator observations
remain present. Privileged means information available directly from the
simulator, such as the object's pose, rather than estimated from a camera.

## Why this design

Format conversion should preserve meaning. The old task remains labeled
`xlerobot_left`; it is not relabeled SO-101 merely because both have six joints.
A separate SO-101 schema fixture checks the installed package's ordered `.pos`
feature names against the pinned SO-101 asset. It is synthetic test data.
Simulator radians and normalized targets remain explicitly documented;
hardware calibration is not inferred from matching names.

Timestamps are frame index divided by control rate: derived simulation time,
not measured camera capture time. Original metadata and both payload hashes
remain in the export manifest. Every array is checked through the real LeRobot
loader before the staged directory is atomically published. Existing output is
never replaced, and a failed export cleans its own staging directory.

LeRobot needs a separate Python/dependency stack, installed only after approval.
Platform-specific locks keep that stack reproducible without changing the
environment behind the previous learning experiment. Optional tests exercise
the real loader, full-state round trips, corrective labels, terminal states,
failure cleanup, and destination preservation. The base suite explicitly skips
these tests when LeRobot is absent; that skip is not acceptance evidence.

[Setup and exact mapping](../LEROBOT_EXPORT.md) explain reproduction and API
sources. The future ACT comparison still needs an explicit full-state adapter
and training-only normalization; export-wide statistics are not training stats.

**Interview question:** Why store both action streams?
**Answer:** Learning needs the expert's corrective label, while replay needs the
noisy command that actually produced the recorded next state.
