# P3.5: webcam controls and simulation timing (partial)
The software is implemented; **live acceptance remains unmeasured**. Scripted
hand fixtures, host-clock simulation checks and black-image model inference do
not establish human demonstrations or webcam latency. No real motors are used.
`MotionSource.read()` returns a new timestamped hand frame or `None`. OpenCV
capture and MediaPipe inference use separate workers with one latest-value slot
each. Capture keeps draining while inference processes a frame. Missing or
ambiguous hands trigger the watchdog: an input-age check that requests hold,
then rest. Only the capture worker releases the camera. A blocked native read
causes a bounded shutdown timeout; resources stay with their worker. Cleanup
attempts both source and backend, preserves the original error, and reports
later failures as notes. Images are not saved.
MediaPipe world landmarks are hand-centered, so they provide finger shape and
palm orientation, not global wrist position. Mapping uses changes from a neutral
pose: image XY and apparent palm size as a depth control proxy. Wrist rotation
also changes palm size; this is **not metric wrist tracking**. Calibration checks
image dimensions, geometry, camera/model identity and spec/profile hashes.
Each latency run preserves the exact calibration, spec and profile bytes used.
Spec snapshots retain paths relative to the original spec location; they are
evidence copies, not standalone relocated robot models. Invalid profile values
and calibration dimensions are rejected before capture starts.
SO-101 uses inverse kinematics (IK), which finds joint positions for a requested
hand pose, plus pinch-to-gripper control. G1 uses both wrists. LEAP maps finger
bend changes to named joints, leaving unmapped spread joints at rest. Profiles
hold robot-specific choices. Limits bound commands; they do not guarantee
reachable targets or collision-free motion. Handedness scores identify left/right
classification confidence; unavailable tracking confidence remains null.
Nominal simulation ticks determine command limits; real elapsed time determines
input age. Whole-period overruns stop execution without catch-up commands. The
recording hook receives post-step state, commands, clamps and timestamps. Latency
includes only unique, fresh, valid frames actually applied. Capture/inference
counts and traces disclose excluded input. The endpoint is host capture return
through simulation-step completion, excluding sensor exposure and driver delay.
Use the isolated vision environment and native build, then
`python -m scripts.fetch_hand_model` and `python -m scripts.smoke_hand_model`.
`python -m xert calibrate --help` and `python -m xert latency --help` describe
explicit camera commands. Choose fresh output paths. Escape on Windows or Ctrl-C
stops a run. Regression checks cover runtime, safety, mock capture and calibration.
Remaining acceptance: verify known left/right hands in the actual camera view,
capture neutral calibration, and run `--duration 300` for each embodiment.
