# P7: packaging, and why numbers come only from the ledger

The README is rewritten around the pipeline diagram. It marks each stage as
complete, partial (software reviewed, waiting on a live run or human data) or
not started, and links its explainer. It quotes no results. The demo
video is still to be made.

`scripts/resume_numbers.py` prints every number that may go on a resume, each
next to its ledger row ID. It reads `results/ledger.jsonl` and nothing else:

- A correction is a new row naming the old ID, in `superseded_id` or in its
  notes. Named rows are dropped, never edited.
- Of the rest, the latest row per slice, experiment, embodiment, metric, phase
  and training seed is kept. Phase and training seed are part of that key
  because one experiment writes a row per seed; dropping them would quietly
  hide all but one seed.
- Rows from a dirty working tree are printed but labelled DIRTY, because their
  source cannot be rebuilt from the commit alone.
- Each value is printed exactly as stored, beside its backend (`mujoco` is
  simulation, `so101_hw` is hardware), sample count `n`, confidence interval and the
  row's own caveat.

**Why only the ledger.** A number typed into a README has no provenance. Nobody
can tell which code, configuration, seeds or data produced it, or whether a
later run replaced it. Typed numbers also drift: the old README quoted test
counts and success rates that later work had made out of date. A ledger row
carries its commit, dirty flag, backend, seeds, config and artifact paths, and
rows are append-only, so a mistake is corrected in the open with a new row.
Printing the row ID beside each value means any number on a resume can be traced
back to its evidence in one step, and a simulation result can never lose its
`mujoco` label along the way.

The script has one test on a temporary ledger. It checks that a superseded row
and an older repeat disappear, that values come out exactly as stored, and that
the simulation label is printed.

**Interview question:** Where does the number on your resume come from?

**Answer:** From one row in an append-only ledger; I can give its ID, and that
row names the commit, config, seeds and saved artifacts that produced it, and
says it was measured in simulation.
