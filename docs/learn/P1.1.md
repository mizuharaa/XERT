# P1.1 — Why small action error did not produce a grasp

Added `scripts/diagnose_learning.py`: a reproducible single-episode overfit probe,
saved model weights and state/action traces, per-joint error plots, and append-only
ledger measurements. This is **MuJoCo simulation**, using the pinned XLeRobot
left arm; it establishes neither hardware performance nor held-out learning.

## Evidence, in the requested diagnostic order

1. **Overfit and rollout.** A multilayer perceptron (MLP, a feed-forward neural
   network) trained on seed 100 failed when feeding back its own resulting states.
   An ACT-style action-chunk model also failed. A time-only MLP control learned
   the same trajectory and succeeded on that exact training seed. All outputs
   came from learned weights; neither control used expert actions at inference.
2. **Open-loop comparison.** With the matched training budget, the full-state
   MLP's predictions on recorded states had mean absolute action error **0.003443**.
   Replaying those predictions completed the task, whereas executing the same
   model with live observations failed before lifting. See
   [joint errors](../../results/p1.1/mlp_matched_2000/joint_errors.svg) and
   [raw outcomes](../../results/p1.1/mlp_matched_2000/summary.json).
3. **Normalization.** Production `train` splits whole episodes before computing
   mean/scale, excludes terminal observations, and shares `_normalize` with
   inference. Existing regression checks cover held-out outliers. Small scales
   amplify drift: the failed MLP reached a normalized wrist-roll velocity above
   **147,000**. Raising the scale floor or freezing constant features alone did
   not rescue it; those failed probes remain recorded.
4. **Time/horizon.** Every diagnostic uses the same environment horizon. The
   observation is `step / horizon`; the production evaluator rejects a mismatched
   horizon contract. That mismatch does not explain this reproduction.
5. **Gripper.** The actuator accepts continuous absolute position targets; there
   is no missing binary decoder. Successful time-only control had greater gripper
   prediction error than the failed matched full-state model, so aggregate gripper
   error alone does not explain failure.

**Finding:** feedback creates states outside the demonstrated trajectory; failure
is consistent with compounding drift. This is *distribution shift*:
the states encountered at execution differ from training states. The paired
replay isolates this failure without changing physics or action decoding. The
time-only control proves this trajectory can be learned, but cannot establish
recovery or generalization. More demonstrations with corrective labels are the
next experiment, not a claimed fix. Historical checkpoints were not available
for an exact reconstruction of every earlier failure.

All reported metrics come from the `P1.1` rows and linked artifacts in
[`results/ledger.jsonl`](../../results/ledger.jsonl), linked to configs, weights,
plots and traces. Earlier source snapshots were reconstructed and hash-checked;
the final matched run saved its source directly. Earlier
teacher-forced replays stop at the demonstration length; their unset failure
reason means incomplete settling, not a completed failed trial.

Reproduce with `python -m scripts.diagnose_learning --output <new-directory>
--epochs 2000`; add `--time-only` for the successful in-sample control. The
production trainer still requires an episode-level validation split.

**Interview question:** Why can a low prediction error still fail in simulation?
**Answer:** Small mistakes change the next state, and a model trained only on
clean expert states may magnify those unfamiliar inputs on every subsequent step.
